# rtpengine-tui

Терминальный интерфейс к listen-cli rtpengine (медиа-релей sipwise), тому же интерфейсу, через который работает `rtpengine-ctl`. Ходит на машины с rtpengine по SSH и выполняет там те же команды: сессии и детали звонков, terminate, лимиты и таймауты на лету, интерфейсы и порты, статистика. Читает `rtpengine.conf` и `rtpengine-recording.conf` и показывает их таблицей с проверкой опций по версии rtpengine на хосте. Навигация vim-клавишами, темы, интерфейс на английском или русском.

English version: [rtpengine-tui.md](rtpengine-tui.md).

![rtpengine-tui на эмуляторе](demo.gif)

## Сборка

Нужен Go 1.22+.

```sh
make build            # ./bin/rtpengine-tui и ./bin/rtpengine-tui-mock
make test
make install          # в $GOPATH/bin
```

Или скачать бинарник из [Releases](https://github.com/napadailo/voip-tui/releases).

## Подключение

Конфиг лежит в `~/.config/rtpengine-tui/config.yaml` (или `$RTPENGINE_TUI_CONFIG`). Пример печатает `rtpengine-tui -sample-config`:

```yaml
currentHost: rtp-prod-1
theme: default               # :themes показывает все
language: ru                 # en или ru; без этого берётся из LANG, :lang переключает
refreshSeconds: 5
ssh:
  user: admin                # общие настройки, ~/.ssh/config тоже работает
hosts:
  - name: rtp-prod-1
    address: rtp1.example.com        # ssh-адрес или алиас из ~/.ssh/config
    labels: {dc: dc1, env: prod}     # или просто метка: labels: prod, или список: [prod, dc1]
  - name: rtp-prod-2
    address: admin@10.0.0.12
    sudo: true                       # читать конфиги и звать rtpengine-ctl через sudo -n
    via: ctl
  - name: rtp-lab
    address: rtp-lab
    cli: 127.0.0.1:9900              # listen-cli; по умолчанию берётся из rtpengine.conf
    version: mr11.5                  # если rtpengine --version недоступен
    configFile: /etc/rtpengine/rtpengine-lab.conf
    logCommand: grep -hF -- {callid} /var/log/rtpengine/rtpengine.log
```

Без конфига: `rtpengine-tui -address rtp1.example.com`. Флаг `-c` задаёт стартовую команду: `rtpengine-tui -host rtp-prod-1 -c config`.

SSH идёт через системный `ssh`, поэтому работают алиасы, ProxyJump, агент и known_hosts из `~/.ssh/config`. Соединение с хостом одно на всё время работы (ControlMaster), частые обновления его не открывают заново.

Как команды доходят до rtpengine (`via`):

| via | Как | Что нужно на хосте |
|---|---|---|
| `tunnel` (по умолчанию) | `ssh -W <listen-cli>`: TCP-канал внутри SSH до listen-cli | ничего, кроме разрешённого в sshd TCP forwarding |
| `ctl` | `rtpengine-ctl [-ip -port] <команда>` на хосте | rtpengine-ctl (perl, Config::Tiny) |
| `direct` | TCP к listen-cli прямо с этой машины | listen-cli, доступный по сети |

Адрес listen-cli берётся из `cli:` в конфиге, иначе из `listen-cli` в rtpengine.conf хоста, иначе `127.0.0.1:9900`.

## Клавиши

| Клавиша | Действие |
|---|---|
| `j` `k` `g` `G` | вниз, вверх, в начало, в конец |
| `ctrl-d` `ctrl-u`, `ctrl-f` `ctrl-b` | полстраницы, страница |
| `H` `M` `L`, `h` `l` | верх, середина, низ экрана; прокрутка колонок |
| `enter`, `esc` или `q` | провалиться внутрь, вернуться назад |
| `:` | командная строка (автодополнение по `tab` и стрелкам, учитывает историю) |
| `/` | фильтр строк (regex, `!` в начале инвертирует); в тексте - поиск, `n` `N` |
| `space` | в сессиях отметить строку (terminate работает по отмеченным), в списке хостов выбрать хост |
| `o` `O` | сменить колонку сортировки, обратный порядок |
| `ctrl-r` | обновить экран |
| `?` | справка |
| `:q`, `ctrl-c` | выход |

Хосты: `enter` открывает сессии хоста, `space` делает хост текущим (отмечается `*`, к нему относятся команды вроде `:config` и `:limits`), `c` конфиги, `m` лимиты, `i` интерфейсы, `p` прокси, `d` описание хоста, `s` интерактивный ssh.

Сессии: `enter` детали звонка, `ctrl-k` terminate отмеченных или текущего (с подтверждением), `v` переключает all, own, foreign, `D` отладочный лог по звонку (mr9.5+), `L` лог звонка, `a` авто-обновление.

Прокси (`p` или `:proxies`): звонки хоста, сгруппированные по сигнальному прокси, то есть по адресу, с которого пришли NG-команды (поле `proxy` в `list sessions`). Группировка идёт по IP без порта: исходный порт у прокси эфемерный, обычно свой у каждого воркера, и число разных портов показано в колонке SOCKETS. Для каждого прокси видно, сколько звонков и какая это доля, сколько из них own и foreign, когда пришёл последний звонок и сколько длится самый старый. С mr8.5 колонки NG добавляют, что каждый прокси прислал с момента запуска, по `list jsonstats`: все команды NG, offer, answer и delete, ошибки и среднее время обработки offer. `enter` открывает сессии только этого прокси.

Детали звонка: вывод `call <id> info` (до mr10.5 `list sessions <id>`) разобран по сторонам звонка. Сверху сводка, идёт ли RTP в обе стороны, время создания и последнего сигналинга, владелец и redis. Ниже путь медиа «caller ⇄ rtpengine ⇄ callee», где адреса rtpengine подписаны именами интерфейсов из `list interfaces` (mr7.5+; при общем адресе интерфейс определяется по диапазону портов), и по каждой стороне таблица потоков: от какого пира на какой порт rtpengine, пакеты, байты, ошибки, средняя скорость, давность последнего пакета и кто его обработал, kernel или userspace (mr12.5+). Счётчики входящие: сколько rtpengine получил от этого пира. Давность считается по часам ноды, а не локальной машины, поэтому расхождение часов на неё не влияет. Если поток молчит, давность подсвечивается жёлтым или красным, а «nothing received» на RTP означает односторонний звук. `y` переключает на вывод как есть, такой же, как у `rtpengine-ctl`. `D` включает или выключает отладочный лог по звонку, `L` открывает лог звонка.

Конфиг: `enter` или `d` карточка опции (значение в файле и в работе, статус, описание, релизы, где она есть), `v` все строки, только секция демона или только находки, `y` и `Y` исходные rtpengine.conf и rtpengine-recording.conf.

Лимиты: `e` или `enter` подставляет `:set <имя> ` в командную строку.

## Лог звонка

`L` в деталях звонка или в списке сессий открывает строки лога rtpengine про этот звонок, новые внизу.

- `f` включает слежение: при каждом обновлении дочитываются строки после последней показанной, окно держится внизу, если его не прокрутили вверх (`G` возвращает в конец). Повторное `f` или выход из окна выключает слежение.
- `ctrl-r` один раз дочитывает новые строки.
- Окно держит последние 5000 строк, тогда в заголовке видно, сколько их всего. `s` сохраняет весь лог звонка, а не только видимое, в `downloadDir` как `log_<call-id>-<время>.log`.

По умолчанию лог берётся командой `journalctl -t rtpengine --since <начало звонка> -o short-iso-precise | grep -F -- <call-id>`: под systemd в journald попадает лог rtpengine и при syslog, и при `log-stderr`. Слежение читает journald с секунды последней показанной строки, а не с начала звонка. Если rtpengine пишет лог в другое место, для хоста задаётся `logCommand`: `{callid}` заменяется на Call-ID в кавычках для shell, `{since}` на значение для `--since` у journalctl. Пользователю без доступа к журналу нужен `sudo: true` или группа `systemd-journal` либо `adm`.

`D`, а потом `L` - обычная пара: включить отладочный лог для одного звонка и смотреть его строки здесь.

## Команды

| Команда | Что делает |
|---|---|
| `:hosts [имя]`, `:nodes` | список хостов или переключение; `:<имя хоста>` тоже переключает |
| `:sessions [all\|own\|foreign\|<call-id>]` | `list sessions` |
| `:config` | rtpengine.conf и rtpengine-recording.conf таблицей, с проверкой по версии и сравнением с `params current` |
| `:limits` | лимиты и таймауты (`list maxsessions`, `list timeout` и другие), значения из rtpengine.conf рядом |
| `:set <имя> <значение>` | `set maxsessions 2000` и т. п., с подтверждением; в rtpengine.conf не пишется |
| `:interfaces` | интерфейсы и занятость портов (mr7.5+) |
| `:stats` (`:totals`, `:counters`, `:jsonstats`, `:transcoders`) | панель статистики из `list jsonstats` (mr8.5+): сессии, трафик в секунду, итоги с запуска, качество, команды NG, интерфейсы, перекодирование (цепочки, скорости, итоги с mr11.5); `y` показывает JSON, `s` сохраняет его. До mr8.5 текстом `list counters`, `list totals` и `list transcoders` (mr7.5) |
| `:params [current\|start\|diff]`, `:revert` | runtime-конфигурация, откат к стартовым значениям |
| `:terminate all\|own\|foreign\|<call-id>` | завершить звонки, с подтверждением |
| `:active`, `:standby` | перевести все звонки в owned или foreign (mr8.5+), с подтверждением |
| `:proxies` | звонки по сигнальным прокси и их команды NG с запуска (mr8.5+): offer, answer, delete, ошибки, среднее время offer; `enter` открывает звонки одного прокси |
| `:keyspaces` | подписки на redis keyspace (`kslist`) |
| `:cli <команда>` | любая команда CLI как есть, например `:cli list maxsessions` |
| `:describe`, `:info` (`:loglevel`) | версия, процесс, пути конфигов, модуль ядра, уровни логов по подсистемам (до mr9.5 один общий; `e` открывает таблицу уровней: `+`/`-` на шаг, `enter` ввести число, `a` для всех подсистем), какие команды CLI есть на хосте |
| `:theme [имя]` | сменить тему, без имени показать список |
| `:lang [en\|ru]` | сменить язык интерфейса, без аргумента показать текущий |

## Язык интерфейса

Интерфейс есть на английском и русском. Язык берётся из флага `-lang`, потом из `language:` в конфиге, потом из `LC_ALL`, `LC_MESSAGES` или `LANG`. Если ни там, ни там нет поддерживаемого языка, интерфейс будет на английском. `:lang ru` и `:lang en` переключают язык на лету, открытые экраны перерисовываются сразу. В конфиг выбор не записывается.

Переведено всё, что пишет сам rtpengine-tui: подсказки, справка, заголовки и колонки, статусы, пояснения в деталях звонка, проверке конфига и разборе шаблонов. Не переводятся имена из rtpengine (команды CLI, опции, флаги NG, `own`/`foreign`, `offer`/`answer`, RTP, SDP), их ищут в логах и документации. Описания опций конфига тоже переведены. Рядом с каждым переводом хранится английский текст, с которого он сделан: если `make gen-rtpengine` принесёт другой, показывается английский, а `make gen-rtpengine` и тест `TestOptionTranslations` перечисляют, что обновить. Описания NG-флагов в разборе шаблонов пока остаются на английском.

Строки в коде пишутся по-английски и оборачиваются в `T()`/`Tf()`, а `N()` помечает текст, который переводится при отрисовке (заголовки, подсказки). Каталоги строк rtpengine-tui лежат в `internal/rtpengine/locale_ru.go`, строки общего каркаса в `tui/locale_*.go`, описания опций в `internal/rtpengine/options_ru.go`. Тесты `internal/rtpengine` и `tui` разбирают исходники и для каждого языка падает, если у помеченной строки нет перевода, если в каталоге есть лишний ключ или если в переводе другие `%`-подстановки. Вторая проверка падает, если текст уходит в ошибку или строку статуса без `T()`. Выравнивание считается по ширине в колонках терминала, широкие символы занимают две.

Новый язык: каталог в `tui` и в `internal/rtpengine` (регистрируется через `i18n.Register`), файл описаний опций в `internal/rtpengine` и строка в `optionTranslations`. Тесты сами покажут, чего не хватает.

## Версии rtpengine

Версию rtpengine-tui определяет так: `version:` из конфига, потом `rtpengine --version`, потом версия пакета (`dpkg`, `rpm`). Набор команд CLI берётся из ответа `help` (есть с mr9.5). Для более старых релизов используется таблица ниже, а если версия неизвестна, она оценивается по доступным командам и показывается как `≥mrX.Y`.

Команды CLI по релизам, по `daemon/cli.c` веток sipwise/rtpengine mr6.5 … mr13.3 и master:

| Релиз | Что появилось |
|---|---|
| mr6.5 | `list` numsessions, sessions, totals, counters, max*, *timeout, loglevel, redis*, controltos; `set` для них же; `terminate`; `params`; `ksadd`, `ksrm`, `kslist` |
| mr7.5 | `list interfaces`, `list transcoders` |
| mr8.5 | `list jsonstats`, `active`, `standby` |
| mr9.5 | `list loglevels`, `list/set deletedelay`, `debug`, `help` |
| mr10.5 | `call <id> info\|terminate\|debug\|tag` |
| mr11.5 | `set redisdisable` |
| mr13.2 | `usage`, `media` (сборки с транскодингом) |

Форматы ответов тоже менялись, клиент понимает оба варианта: список сессий `callid: … \| deletionmark:` до mr11.5 и `ID: … \| del: … \| rec:` с mr12.5; `params` с именами опций (`max-sessions`) до mr8.5 и с именами полей (`max_sessions`, `timeout_us` в микросекундах) позже; сообщение о неизвестной команде `Unknown or incomplete command` до mr13.1 и `Unknown command` с mr13.2.

Команду, которой нет в версии хоста, rtpengine-tui не отправляет и пишет, с какого релиза она есть: `"list interfaces" needs rtpengine mr7.5+, host runs mr6.5.9.12`.

## Проверка rtpengine.conf

Конфиги читаются по SSH (`cat`, с `sudo: true` через `sudo -n`). Путь и секция берутся из командной строки работающего процесса (`--config-file`, `--config-section`), иначе из `configFile`/`recordingConfigFile` в конфиге, иначе `/etc/rtpengine/rtpengine.conf` и `/etc/rtpengine/rtpengine-recording.conf`.

Статусы строк:

| Статус | Значит |
|---|---|
| `ok` | опция есть в этой версии |
| `runtime differs` | значение в файле не совпадает с `params current`: поменяли через `set` или не перезапустили после правки |
| `overridden` | ключ задан в секции ещё раз ниже, работает последний |
| `not in version` | опция из другого релиза: `added in mr12.5, host runs mr11.5` или `dropped after …` |
| `unknown` | такой опции нет ни в одном релизе, обычно опечатка; rtpengine с ней не стартует |
| `interface`, `templates`, `section` | секции интерфейсов (`interfaces-config`), шаблонов сигнализации (`templates`) или чужие секции, которые демон не читает |

Таблица опций (имя, описание, аргумент, в каких релизах есть) сгенерирована из `daemon/main.c`, `recording-daemon/main.c` и `lib/auxlib.c`: `make gen-rtpengine` скачивает исходники и пересобирает `internal/rtpengine/options_gen.go`. Опция считается доступной, если она есть в ближайшей ветке снизу или сверху от версии хоста, поэтому для промежуточных релизов (например mr10.0) возможны пропуски, но не ложные срабатывания.

### Шаблоны сигнализации

Секция, которую называет опция `templates` (mr13.2+), хранит шаблоны: строки NG-флагов в том же синтаксисе, что аргумент `rtpengine_offer()` в Kamailio или OpenSIPS. `enter` на строке шаблона в `:config` разбирает его по токенам так же, как это делает парсер демона (`control_ng_flags_parser.c`), и для каждого показывает:

- что это: ключ `key=value`, флаг, replace-флаг (`replace-origin`, `replace=[...]`), операция с кодеками (`codec-strip-G729`, `codec=[transcode=[PCMA]]`), сокращение транспорта (`RTP`, `SRTP`, `AVPF`, `DTLS`, из которых складывается итоговый `transport-protocol`) или направление (`internal`, `external`, `direction=`);
- описание из `docs/ng_control_protocol.md`, а для значений вроде `ICE=force` или `rtcp-mux=[offer require]` ещё и описание каждого значения;
- ошибки: неизвестный флаг (rtpengine пишет в лог предупреждение и игнорирует его) с подсказкой ближайшего имени, отличие только в регистре (имена регистрозависимы), флаг из другого релиза.

Там же видно, как шаблон применяется. Шаблон с именем NG-команды (`offer`, `answer`, `delete`…) rtpengine применяет к каждой такой команде сам, а `default` применяется ко всем сообщениям. Остальные срабатывают только там, где прокси передаёт `template=<имя>`. В таблице `:config` шаблон с ошибками получает статус `unknown` или `not in version`, на хостах до mr13.2 все шаблоны помечаются `not in version`.

Таблица ключей и флагов NG-протокола (`internal/rtpengine/ngflags_gen.go`) тоже генерируется `make gen-rtpengine`: имена со всеми алиасами берутся из `call_ng_main_flags`, `call_ng_flags_flags`, `call_ng_flags_replace` и `call_ng_codec_flags` (в master они переехали в `daemon/call_flags.c`), описания берутся из раздела `offer` документации, по веткам mr13.2, mr13.3 и master.

## Мок-сервер

`rtpengine-tui-mock` имитирует listen-cli выбранного релиза: команды и форматы ответов соответствуют версии, звонки появляются и завершаются, `set`, `terminate`, `debug`, `params`, keyspaces работают. С `-confdir` он кладёт рядом примеры rtpengine.conf и rtpengine-recording.conf с намеренными проблемами (опечатка, опции из новых релизов, повтор ключа, значения, изменённые на лету), файл лога на каждый хост в формате journald и конфиг для rtpengine-tui, который на всё это указывает.

```sh
./bin/rtpengine-tui-mock -fleet -confdir bin/mock-etc &     # mr6.5, mr9.5, mr11.5, mr13.3 на портах 9901-9904
./bin/rtpengine-tui -config bin/mock-etc/rtpengine-tui.yaml

./bin/rtpengine-tui-mock -listen 127.0.0.1:9900 -version mr12.5.1.3 &
./bin/rtpengine-tui -address local -cli 127.0.0.1:9900
```

`make demo-rtpengine` запускает эмулятор и печатает вторую строку. На эмуляторе работают тесты (`make test`), в том числе UI-тесты на виртуальном экране, а `make demo-gif` записывает анимацию выше.
